# 账单导入格式与统计口径

当前实现按表头识别格式，不按文件名猜来源。以下格式来自合成测试样例，仍需用你的实际导出文件确认适配。

## CSV

支持UTF-8（含BOM）、GB18030及UTF-16LE BOM；支持逗号分隔、引号、引号内逗号/换行和双引号转义。允许表头前存在账单说明行、时间范围等内容。

微信典型表头：

```text
交易时间,交易类型,交易对方,商品,收/支,金额(元),当前状态,交易单号
```

支付宝典型表头：

```text
交易创建时间,交易分类,交易对方,商品说明,收/支,金额（元）,交易状态,交易订单号
```

别名：时间也接受“付款时间”；商家接受“商户名称”“收款方”；金额接受“金额”“交易金额(元)”；方向接受“收支”“资金状态”“收支类型”；交易号接受“交易号”。中文/英文括号会归一化。

至少需要时间、商家、金额、收支方向。来源由导出说明中的微信/支付宝，或微信“交易单号”、支付宝“交易号/交易订单号”确定。不确定方向或来源时拒绝猜测。

支持时间例：`2026-10-16 12:30:00`、`2026/10/16 12:30:00`；缺秒允许。按北京时间解析。金额必须为正数，最多两位小数；无效日期、金额不会强行修正。失败/关闭交易跳过。

## XLSX

支持未加密的标准XLSX：共享字符串、内联文本、富文本拼接、稀疏列，以及交易时间列的Excel数值日期。扫描工作表，读取首个匹配账单表头的工作表。

- 原始文件不超过20MB；ZIP成员总解压量不超过32MB，单工作表不超过10万行。
- 账单ZIP先解压，选择其中CSV/XLSX；不支持PDF、旧版XLS或密码加密工作簿。
- 不在手机端执行表格公式；使用已缓存的单元格值。应导入原始账单，而非包含自定义公式的汇总工作簿。

## 交易身份与退款

- 同渠道、同类型、同交易号视为同一笔；不同交易号的同金额消费分别保留。
- 同一文件由内容摘要识别，重复导入不会新增。文件行来源与通知事件来源持久化，并随备份保存。
- 无交易号时，渠道、金额、时间邻近与商家相似只触发待确认，不直接删除。
- 退款有独立退款单号时以该编号去重。原消费订单号仅保存为关联，不用它合并多笔部分退款。
- 原消费行已退款但没有单独退款日期/金额：待确认，人工保留原消费并另记实际退款。
- 退款在到账日期抵减，故某天/某月净消费可以为负数。分类占比使用支出总额；趋势、排名和增减使用净消费。
- 导入不会覆盖人工类别与备注。来源文件中的商家仍用于去重和兼容，界面、搜索与CSV导出围绕分类和备注。

## 合成样例验收

在空账本导入 `samples/wechat-synthetic.csv` 和 `samples/alipay-synthetic.csv`：共9条有效记录（含退款、转账）；2026年10月截至16日有5笔消费，支出115.30元、退款20.00元、净消费95.30元。失败付款不计入，50元转账不计入消费。重复导入上述文件不增加记录。
