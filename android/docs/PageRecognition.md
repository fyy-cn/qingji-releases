# 支付页面识别实验（1.5.0）

本次用于验证你手机上的微信、支付宝支付页面能否提供商家与金额。默认关闭，开启后新识别记录先进入待确认，不保证所有交易都能识别。

## 在手机上验证

1. 在清记设置中检查更新，覆盖安装1.5.0，不要卸载。
2. 设置 → 支付页面识别（实验） → 开启页面识别。阅读说明，点击“同意并前往授权”。
3. 在系统无障碍设置的已安装服务中找到“清记 · 支付页面识别（实验）”，由你手动开启。系统设置名称随版本变化，以手机显示为准。
4. 回到微信或支付宝，重新打开一笔已有的、已成功支出的交易详情，等待约1秒。可直接用已有账单验证，无需专门消费；本功能不会替你打开页面或执行付款。
5. 返回清记 → 设置，看最近检测状态；点击“查看待确认账单”，核对商家、金额、时间和分类。没读到的字段会提示，时间缺失时暂用识别时间，核实前不计入消费。
6. 如果本来已有同一笔消费，先看是否被标为疑似重复。相同渠道交易号自动补全；没有可靠交易号时由你确认合并，不能只凭金额相同自动合并。
7. 如无结果，点击“复制识别诊断”，将文本反馈给开发者。诊断包括系统/支付App版本、服务状态、页面类名、可读文字片段数量和结果，不包含商家、金额、交易号、完整页面或聊天内容。
8. 可随时点“关闭页面识别”，停止处理并请求关闭该服务；也可以在系统无障碍设置中撤销授权。

如果系统不允许开启，先保留系统提示反馈，当前版本不尝试绕过系统限制。系统授权后仍可能读不到页面，这正是本实验需要验证的内容。

## 数据与边界

系统授予的页面读取权限范围较大，并非只授权一张支付页面。代码默认只接收微信/支付宝的窗口变化事件；选择校园应用后，只额外接收该应用。微信/支付宝先检查已知支付窗口名单；校园应用按选择的包名限定，读取后再以消费详情模板判断。仅提取可见节点文字；密码、输入框、敏感节点和其他App节点会跳过。完整页面只在内存中短暂处理，通过支付模板后仅保存提取的交易字段；不保存页面全文，不上传页面。诊断只保存在本机，复制后由你自行决定是否分享。

本服务采用只读模式，不申请手势、截图、键盘监听、触摸探索或其他应用窗口遍历能力。它不是为残障用户提供辅助交互的工具，Android31以上明确标记isAccessibilityTool=false；不会尝试读取平台限制的敏感节点。

初始模板只处理成功的人民币支出，需同时具备支付成功/交易成功和支出依据。退款、转账、充值、还款、收入、外币及未成功交易不通过本实验采集，继续使用原通知流程或导入。页面/金额不明确时保留待核实状态，不据此生成已确认消费。

付款码被扫、自动扣费、未展示结果页、页面没有可访问文字、支付App模板变化或后台被限制时，仍可能遗漏。旧交易详情没有时间时不能假定它发生在今天，需要手动核对时间或导入源账单补齐。

重复节点更新在当前页面会复用同一个事件；识别到不同交易号或离开后重新进入会建立新事件。没有交易号时仍可能产生疑似重复，需要你核对。已有人工分类、备注和时间不会被页面自动覆盖。新记录会使用现有商家规则与关键词推荐分类；本版不新增云端模型。

尚未连接小米真机验证实际微信/支付宝页面；合成页面和自动测试只验证代码行为，不代表支付页面覆盖率。授权开关不进入账本备份，恢复备份不会自动授予权限。

## 1.5.0适配与校园来源

已将反馈中的微信`com.tencent.mm.plugin.webview.ui.tools.MMWebViewUI`加入窗口入口，并允许遍历不提供可见文字的WebView容器以查找可见子节点。进入读取流程后，仍须通过交易模板；普通网页不会仅凭窗口类生成账单。如果系统返回空文字，诊断会明确显示，不再与未适配窗口混为一谈。

选择交我办后，可读取所选App的消费详情。校园页面可用明确“交易类型：消费/支出”替代成功状态作为候选依据，缺少成功状态时提示核实；所有新页面记录均待确认。余额不替代消费金额，充值页面排除。实际学校版本能否提供节点和模板仍待真机验证。通知采集与页面实验独立，关闭页面实验不影响通知记账。[校园选择与通知排查](NotificationCapture.md)。
